运维手册

目录结构、端口、备份恢复、升级与常见故障处理。

运行架构

程序自身就是 HTTP 服务器；nginx 只做入口代理。后台端口不要直接暴露公网。

目录结构

路径作用是否可删
cmsGo 主程序，单文件否
html/前台、后台、安装向导、API 文档静态资源否
data/tpl/站点模板与主题否（会丢模板）
data/cache/页面/数据缓存可清空
data/uploadFile/用户上传文件可迁移，勿随意删
data/app/安卓 / iOS 安装包等附件可迁移
data/key/、data/token/实例授权与令牌数据否（迁移时保留）
config.conf数据库与端口配置，含明文密码否（权限 600）
install.lock安装锁定与完整性校验否（重装除外）
stdout.log服务标准输出可轮转

备份与恢复

热备份

APP=/www/wwwroot/iycms
DATE=$(date +%F_%H%M)

# 程序与数据（排除缓存与日志）
tar czf /backup/iycms_$DATE.tar.gz \
  -C $APP cms html data config.conf \
  --exclude='data/cache/*' --exclude='stdout.log'

# 数据库
mysqldump --single-transaction --routines --triggers \
  -uiycms -p iycms > /backup/iycms_db_$DATE.sql

sha256sum /backup/iycms_$DATE.tar.gz /backup/iycms_db_$DATE.sql

恢复

systemctl stop iycms
cp -a /www/wwwroot/iycms /www/wwwroot/iycms.bak.$(date +%s)
tar xzf /backup/iycms_2026-11-07_1200.tar.gz -C /www/wwwroot/iycms
mysql -uiycms -p iycms < /backup/iycms_db_2026-11-07_1200.sql
chown -R www:www /www/wwwroot/iycms   # 若服务以 www 运行
systemctl start iycms
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:51200/

迁移到新机器时，config.conf、data/key/、data/token/、install.lock 必须一起带走，否则可能出现授权或安装状态异常。

升级

  1. 先做完整备份（程序 + 数据库 + data/）。
  2. systemctl stop iycms。
  3. 替换 cms 与 html/，保留 data/、config.conf、install.lock。
  4. chmod +x cms，启动并检查日志。
  5. 验证前台 200、后台可登录、模板与上传文件正常。

官方已停止更新，2.3.4 之后不会再有安全补丁。长期运行建议放在内网或加 WAF / 访问控制，并定期检查 html/ 是否被植入 webshell。

日志与监控

# 实时日志
journalctl -u iycms -f
tail -f /www/wwwroot/iycms/stdout.log

# 建议的 logrotate 配置：/etc/logrotate.d/iycms
/www/wwwroot/iycms/stdout.log {
    daily
    rotate 7
    missingok
    notifempty
    copytruncate
    compress
}
# 最简单的存活检查
*/2 * * * * curl -fsS -o /dev/null http://127.0.0.1:51200/ || systemctl restart iycms

安全加固清单

项目建议
运行用户不要用 root；创建 www 用户并 chown 程序目录
后台暴露面21007 只监听内网或仅允许固定 IP；nginx 后台域名加 Basic Auth / IP 白名单
配置文件chmod 600 config.conf，不要把真实密码提交到 Git
安装目录install.lock 只读；定期比对哈希，防止被替换
上传目录data/uploadFile/ 禁止执行脚本；nginx 对上传目录关闭 PHP/ CGI
备份数据库与 data/ 异地备份，备份文件加密
依赖MySQL、nginx、OpenSSL 保持最新；程序本身无补丁来源

常见故障速查

症状排查顺序
服务起不来systemctl status iycms → journalctl -u iycms -n 50 → 手动执行 ./cms 看报错
端口未监听检查 config.conf 的 httpPort/backendPort 是否被占用（ss -tlnp）
502 / 504nginx 代理地址是否指向 127.0.0.1:51200；程序是否存活
页面样式丢失html/ 是否与 cms 同级、权限是否可读
数据库报错mysql -h127.0.0.1 -uiycms -p iycms -e 'select 1'
后台登录 404确认访问的是 :21007/backend/，而不是前台端口
安装锁定被篡改恢复原 install.lock；检查目录权限与异常登录
